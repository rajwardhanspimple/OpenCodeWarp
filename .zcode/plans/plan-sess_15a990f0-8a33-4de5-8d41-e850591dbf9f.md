## Context

**OpenCodeWarp** (D:\OpenCodeWarp) routes only the OpenCode TUI it launches through the WARP relay (127.0.0.1:41000). The new **opencode-proxy** shim (D:\opencode-proxy, port 4141) serves DeepSeek Harness via `opencode api` → opencode's **background service** (`opencode serve --service`, currently 127.0.0.1:28894) — and that service makes the upstream Zen calls. Today its relay env is accidental (inherited from whatever process first started it); after a reboot or an external restart it can silently go direct, so DSH traffic bypasses WARP and rotation stops helping.

Discovery that makes this clean: opencode 2.2.6 persists env for the background service via `opencode service set env <KEY> <value>` (verified round-trip with `opencode service get` / `unset env`). Writing the relay proxy there makes **every** service start — by DSH, a terminal, or auto-start after reboot — relay-wired. The QuotaWatcher already tails the shared log dir the service writes to, so quota hits from the DSH path will trigger rotation with no new code.

User decisions: **wire traffic only** (no shim lifecycle management), **apply only the stashed probe session-id fix**, **keep the service proxy env set on dashboard exit** (tray mode is expected to run, README documents the caveat).

### Commit 2 — route the opencode background service through the relay

**New `src/OpenCodeWarp.Core/OpenCodeServiceManager.cs`**
- Wraps the `opencode service` CLI (reuse `OpenCodeLauncher.BuildCommandLine` for .cmd shims, pattern from `OpenCodeLauncher.VerifyExecutableAsync` for run-with-timeout):
  - `StatusAsync()` — parse the URL from `opencode service status`; resolve listener PID + start time via a new public `WindowsPortFinder.GetLoopbackListenerOwnerPid(port)` helper (the `EnumerateTcpListeners`/`MIB_TCPROW_OWNER_PID` machinery already exists in `WindowsPortFinder.cs`).
  - `EnsureProxyConfigAsync(proxyUrl)` — read `opencode service get`, compare against desired `{HTTP_PROXY, HTTPS_PROXY, http_proxy, https_proxy = relay; NO_PROXY, no_proxy = localhost,127.0.0.1,::1}`, write only missing/changed keys via `opencode service set env`. Never unset foreign keys. Records `LastConfigWriteAt`.
  - `RestartAsync()` — `opencode service stop` → `opencode service start` → poll for the listener again (like `WaitForServerAsync`). Used only when the running service predates the config write.
- Staleness rule: service running && its process StartTime < LastConfigWriteAt → `RestartNeeded`.

**`AppSettings.cs`** — add `ServiceProxyEnabled` (bool, default **true**), clamped/normalized like the rest.

**`AppController.cs`**
- Construct the manager; in `StartAsync` (after `Relay.StartAsync`, before `Watcher.Start`): if enabled → `EnsureProxyConfigAsync`; if a service is running and stale → confirm via a new `ConfirmServiceRestart` handler (same pattern as `ConfirmRotation`; headless = proceed) → `RestartAsync`. Never auto-*start* the service; it starts on first use by opencode clients.
- In `SaveSettings`: when the relay port changed and the feature is on, re-run ensure and re-evaluate staleness (prompt again if running).
- Shutdown touches nothing (env stays set per decision).
- Expose service state for UI/CLI: `ServiceUrl`, `ServicePid`, `ServiceEnvOk`, `ServiceRestartNeeded`.

**`MainForm.cs`** — extend the OpenCode status card detail with one background-service line: "background service: relay-wired (pid N)" / "restart needed" / "not running"; activity-log entries for config writes and restarts. Startup shows the restart confirmation dialog when stale (via `ConfirmServiceRestart`).

**`SettingsForm.cs`** — checkbox "Route the opencode background service (opencode api / opencode-proxy bridge) through the relay" bound to `ServiceProxyEnabled`.

**`src/OpenCodeWarp.Cli/Program.cs`** — `ocwarp status` gains the service line; small `ocwarp service ensure` command that runs the same ensure + staleness check headlessly.

**`README.md`** — new section: how the DSH → opencode-proxy → background service path gets the WARP exit IP; the Settings toggle; the caveat that DSH/bridge model traffic needs the dashboard (tray) running; note that the shim's own limits (no true streaming, emulated tool calls, upstream free quota) are unchanged and owned by D:\opencode-proxy.
